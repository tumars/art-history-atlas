# 手机画海：手势与动效优化

2026-11-06，针对“星海交互不好”的第二轮实现。保留完整画海、深度景差和星光，不改变四 tab 结构。

## 现状诊断

- 原来点画会调用整个页面的 `render()`，重新创建 422 个画作按钮，并立即重设镜头；点选、切作品、暂停都容易产生不连续感。
- 拖动把屏幕位移固定乘以 2，未考虑被触摸作品的深度；近画与远画跟手程度不同。
- 松手减速使用每帧乘 0.91，没有按真实时间计算；输入频率和刷新率会影响惯性距离。停顿后释放也可能沿用过期速度。
- 逐次输入修改 left / top / width；一次屏幕刷新前可能重复布局。旧动画缺少统一的取消机制。

这些结论来自当前源代码检查，不是已完成真机用户研究的结果。

## 库的对比与选择

2026-11-06 查阅官方资料和 Context7 文档，npm 查询并锁定 `motion@14.9.1`。

| 方案 | 对本任务有用的能力 | 决定 |
|---|---|---|
| [Motion JS](https://motion.dev/docs/animate) | 普通数值动画、弹簧、惯性和可停止的控制器，不要求 React | 采用；驱动镜头数值，继续复用现有投影与图片 |
| [GSAP Draggable](https://gsap.com/docs/v3/Plugins/Draggable/) | 拖拽、速度与惯性衔接；适合复杂拖拽编排 | 可行备选；本次只需一个镜头控制器，避免引入两套动画体系 |
| [PixiJS](https://pixijs.com/8.x/guides/concepts/render-loop) | Sprite 场景、ticker 与 GPU 渲染流程 | 如果后续实测瓶颈在大量图像绘制，可考虑；目前换渲染器不能直接修复点选重建与手势判断 |
| [Three.js](https://github.com/mrdoob/three.js) | 完整三维场景与相机，需管理 GPU 纹理等资源 | 适合真实空间、灯光或着色器需求；本次已有景深投影，不为触摸优化重建 3D 场景 |

Three.js 资源生命周期参考：[WebGLRenderer](https://github.com/mrdoob/three.js/blob/dev/src/renderers/WebGLRenderer.js)、[Texture](https://github.com/mrdoob/three.js/blob/dev/docs/pages/Texture.html)。这里只做架构取舍，没有实际运行四库性能对比，也不宣称 Motion 比其他方案更快。

## 已实现的操作模型

1. **拖动直接跟手**：以按下处画作深度换算屏幕位移；不在拖动时追逐弹簧目标。7px 阈值区分轻触与拖拽。
2. **松手有短惯性**：速度单位为 px/s，按采样时间平滑；Motion inertia 使用 `power: .18`、`timeConstant: 240`。停顿超过 100ms 后释放不继续滑行，减少动态或暂停时无惯性。
3. **轻触刹车**：任何新按下立即停止正在运行的动画；滑行中的一次轻触只刹车，不同时打开作品。
4. **原位选中**：第一次点画更新高亮与短展签，不挪动画作、不重建 DOM；再点选中作品进入详情。
5. **平滑定位**：前后切件、选择时期、回到选中作品由 Motion spring 驱动；新操作随时打断，暂停控制环境漂浮和惯性，不阻止显式导航。
6. **视距控制**：拉远 / 回到选中作品 / 拉近三个具名按钮，沿用原画海距离范围；双指仍交浏览器缩放，多指开始或 pointercancel 立即取消单指拖动。
7. **按帧合并绘制**：位置与尺寸缩放改用 `translate3d + scale`；同一帧多个输入只安排一次绘制。图片仍仅附近加载，星光跟随镜头产生轻微分层位移。
8. **可终止生命周期**：离开页面、进入后台、改变减少动态设置时停止相关动画；卸载清理控制器、rAF、ResizeObserver 与监听器。

### 星空与画框（同日视觉细化）

第一版三层 96 星与暖金框被用户指出星点过于规整、画框过粗。因此改为三层共 60 颗低亮度星点：使用固定种子对横纵坐标独立采样，避免线性关联产生斜排；大小、闪烁周期、相位和峰值独立变化。去除十字亮星、外发光和背景光晕，只保留纯深色背景上的淡淡闪烁。镜头只更新三个星层的轻微视差，不逐帧修改每颗星；星层不接收点击，也不进入辅助技术阅读顺序。

画框衬边从 8px 减至 2px，移除金属渐变、多层压边与选中光晕，采用深灰棕衬边、低对比边线和轻阴影；实际屏幕宽度还会随景深缩小。画框与图像作为整体漂浮，保持完整原作比例；框是界面展陈装饰，不表示作品真实历史画框。暂停、拖动、后台与减少动态设置同时作用于框和星光。

该版[修订截图](../screenshots/mobile-sea-subtle.png)保留为过程记录。用户随后反馈星光几乎不可见且画海缺少纵深，因此继续调整如下。

### 星光可见性与景深修订

- 三层共 72 星，尺寸从 0.6–1.4px 增至 1.1–1.9px；闪烁下限 0.22，随机峰值 0.5–0.75，减少动态时固定 0.48。保留独立随机位置与错峰周期，不恢复规则排布和十字亮星。
- 作品深度归一化后，远景逐渐降低透明度、亮度和饱和度，虚化强度按深度平方增长，最高约 0.4px 显示空间半径；根据连续反馈由 1.7px、0.85px 逐步减轻，保留原有明暗、透视与景差。按投影缩放换算 CSS blur，只在绘制可见作品时更新。
- 近景与选中作品保持清晰，选中作品不受暗化影响；详情图片不应用景深滤镜。细框保持上一轮的 2px 衬边。
- 已核对[当前截图](../screenshots/mobile-sea-depth.png)，构建通过；Chrome 检查 72 星、远景滤镜、点选后清晰、暂停和减少动态生效。滤镜对真机帧率的影响仍需设备实测，不宣称性能提升。

## 成本与验证

- 手机异步 JS 构建由约 35.46 KB / gzip 14.81 KB 增至约 110.85 KB / gzip 41.77 KB，约增加 27 KB gzip；含新增代码和 Motion，不能当作库的独立压缩大小。
- 主页面仍有约 507 KB 的 Vite 分块提示；没有以引入库宣称性能指标已经改善。
- `npm run build`、现有单元测试与手机全流程脚本检查基础回归。
- `scripts/mobile-sea.e2e.mjs` 在 Chrome 触摸模拟中检查 DOM 连续性、定位中间帧、原位选中、暂停、惯性、按住制动、停顿释放、多指取消、视距与减少动态。
- 本轮专项脚本已通过；过程中发现并修正相同动画端点导致惯性被跳过、滑行刹车触摸误开作品两个问题。构建、18 项单元测试通过；[实际页面截图](../screenshots/mobile-sea-motion.png)仅展示画面，不代替动效验证。
- iOS / Android 真机手感、60/120Hz 对比、电量与帧时间仍需设备实测；发布流程见 [部署文档](../deployment.md)。
