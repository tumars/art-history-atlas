- 原型（手机直接打开，私有链接，第五轮为版本 6）：<https://claude.ai/artifact/By6LfNC48QKHwSELjPTpR2>。打包了全部缩略图和 159 张展示图；其余作品在作品页显示缩略图。

第三轮解决“像不像 iPhone App”（结构与手势）；第四轮重做人物部分并尝试柔光渐变的视觉语言；第五轮根据反馈把渐变和重阴影收回，改成安静的底色，画海恢复夜空，并重排长文字。

## 1. 结构与手势（第三轮，保留）

| 问题 | 第二轮 | 现在 |
|---|---|---|
| 导航栏 | 宋体小标题、贴边页眉、自绘返回 | 二级页面：标题随滚动出现，栏背景变为玻璃；返回是玻璃圆按钮。四个 tab 根页面不放标题（底栏已标明当前页，第五轮去掉以节省约 100px），只在状态栏背后留一条滚动时出现的玻璃条 |
| 底栏 | 通栏贴底、四个 tab | 悬浮胶囊：画海、导览、人物、收藏；搜索是独立圆形按钮，点开后 tab 栏变成搜索框 |
| 转场 | 整页替换 | 推入带视差和阴影；缩略图到作品页是缩放转场 |
| 返回 | 依赖浏览器 | 页面任意位置右滑返回（iOS 26 起的全屏返回） |
| 弹层 | 底部抽屉 | sheet 有贴合内容 / 中 / 大三档，可拖动；大档时背后页面缩小 |
| 长按 | 无 | 预览 + 操作菜单 |

导览 = 年表 / 展厅 / 故事（第五轮调整顺序，默认打开年表）；作品页可左右滑动切换同一组作品；全屏看画支持双指缩放、双击放大、下拉关闭。

## 2. 视觉语言（第五轮）

第四轮的柔光渐变、漂移光斑、渐变按钮和发光阴影被认为“太重、太 AI 感”；画海浅色改成“晨光”也不对。第五轮的原则是**颜色只来自作品**，界面本身保持中性。

| 方面 | 第四轮 | 第五轮 |
|---|---|---|
| 背景 | 四团漂移的彩色柔光 | 中性暖灰实色（浅 `#f4f4f1`，深 `#0f0f11`）；作品、人物、展厅、故事页顶部只有一层很淡的线性取色 |
| 卡片 | 72% 半透明白 + 蓝紫色大投影 | 实色白卡（深色 `#1b1b1e`）、0.5px 描边、几乎看不见的投影；圆角 20px |
| 强调色 | 青绿到长春花蓝的渐变，带彩色投影 | 单一墨绿 `#2b7a68`（深色 `#6cc4ad`），只用于主按钮、进度和选中 |
| 发光与装饰 | 关系链中心的旋转彩环、时光带读数针发光、空状态呼吸球 | 全部去掉；选中用描边或实色表示 |
| 动效 | 弹性浮起（带缩放） | 10px 轻微上移淡入；按压回弹、分段控件弹性保留 |
| 画海 | 浅色“晨光”、白色卡纸 | 深色是夜空 `#0b1520`（与正式版一致），两层星点随拖动视差移动并闪烁，tab 栏和状态栏随之变深；浅色是“白天的展厅墙”（见下） |
| 玻璃 | 导航、tab、sheet、菜单 | 保留在导航、tab、sheet、菜单（iOS 自身的材质），降低阴影 |

### 画海浅色：白天的展厅墙

先试过莫奈《印象·日出》的色调（灰蓝晨雾、橙色太阳和倒影），效果不好：画海里的作品本身色彩各异，背景再带一个有主题的颜色和图形，会和作品抢，而且太阳总被作品挡住。

调研美术馆的照明做法：展厅用漫射天光做“像阴天一样没有阴影的”底光，再用射灯把重点作品提出来，重点与背景的亮度比一般在 3:1 到 10:1 之间（[ERCO](https://www.architectatwork.com/en/curated/innovations/uniscan-129347)、[展墙照明综述](https://tmg-lighting.pages.dev/blog/2026-05-02-post-127)）；有天窗的美术馆会把顶部刷白来扩散日光（[Frick Collection](https://coolshadow.com/project/the-frick-collection)）。所以浅色画海不再用颜色，而是用“光和影”：

- 墙：暖灰白灰泥 `#dcd7cd`，叠一层很细的颗粒（SVG 噪点），四角略暗。
- 天光：两团很淡的亮区以 46 秒周期缓慢移动，像云从天窗前经过；随拖动有轻微视差。
- 射灯：选中作品后面的墙上有一圈暖白的光，换作品时光滑过去。
- 投影：光从屏幕上方来，每件作品的影子方向和长度由它在屏幕上的位置决定，拖动画海时影子跟着变，像在墙前走动。影子是模糊的伪元素，只改 transform，不重绘阴影。
- 深色模式不变（夜空），以上图层都不显示。

### 画海：孔明灯式的散落与视差（参考 PC 版）

PC 版画海（`src/sections/hero-space.ts`、`hero.ts`）把作品放在远、中、近三个深度上，按透视缩放；每件作品有 ±6° 的固定倾斜，以底部为轴缓慢摇晃（`lantern-drift`），拖动时随速度侧倾。手机原型按同样的思路：

- 三层：近 1、中 0.74、远 0.52。拖动时每层按自己的系数平移，远处的画移动得少（视差）；远层的画更小，浅色时更淡、更灰（空气透视），深色时更暗。
- 每件作品有固定倾斜（±6°），以底部为轴摇晃 ±1.5° 并上下漂浮，周期 13–25 秒各不相同；拖动时整片画随速度侧倾，松手慢慢回正。
- 选中的作品摆正；如果它在远层，会去掉褪色并放大，像被拉近。
- 深色模式沿用 PC 版的灯：细金边、底部一点暖光。
- 背景色块：从选中作品的上、中、下三段各取一种颜色，画成三块柔边色块，比最远的画更远（视差 0.2），以 36–51 秒周期缓慢漂移变形；换作品时 1.8 秒换色。浅色用 multiply 像水彩染在墙上，深色用 screen 像夜空里的光雾。颜色来自作品，不是固定的装饰色。


### 长文字排版

- 中文标题按分句断行：每个分句是一个 inline-block，只在“，、？”等标点后换行，避免“她为 / 什么”“天 / 顶”这种拆词（CSS `text-wrap: balance` 在中文里会拆词，所以不用）。
- 正文：16px、行高 1.75、两端对齐、段距约 0.9em；导语用宋体 17.5px。时代、大事、相遇的说明 sheet 统一为“灰色年代 → 宋体导语 → 正文 → 灰色小标题”的结构。
- 人物页：一句话简介下面是一行灰色身份信息（取代五个胶囊标签）；新增引语卡片（`quote`）和“评价与影响”（`legacy`），这两个字段以前没有显示；“认识某人”改成编号列表；生平改成“年份 + 当时年龄”在上、正文在下，正文获得整行宽度。
- 阅读页：标题按分句断行；正文两端对齐；选择后的回应改为浅色块。

主要 token 在 `mobile-ios.css` 顶部；分组色通过 `.gc` 在浅色、深色两套之间切换，取色通过 `.page.tinted` 的 `--art`。

## 3. 人物：为什么竖向不行，改成什么

### 竖向时间轴 / 关系图的问题

- 67 人排成 17 列，每列 18px，名字只能竖排，读起来吃力；时间轴约 2400px、关系图约 3000px 长，一屏只能看到很小一段，失去“全部”的意义。
- 关系图里跨越几百年的影响线在中间形成成束的竖线，不选人时几乎无法读。
- 两者都要求“先滚动找到，再精确点中一根细线或小头像”，手机上手指精度不够。

### 调研依据

- 移动端时间线研究建议交互保持简单，**一次只直接操作一个对象**，避免双指手势；有研究用固定的时间线加一个可拖手柄替代平移缩放的大画布（[Maximizing Resolvable Items, MobileVis 2018](https://mobilevis.github.io/assets/mobilevis2018_paper_10.pdf)）。
- 有的时间线组件在手机上改为“拖动手柄刷选、点击查看”，并把联动的多个视图同步到同一个时间点（[Lifeline](https://github.com/evilrabbit/lifeline/wiki)；[Motion Comparator](https://arxiv.org/pdf/2407.02746) 中的联动刷选）。
- 关系网络的研究发现，“附着在一个节点上、只在相邻节点间跳转”更易用，跳转时用形变动画帮助用户保持心理地图（[Egocentric Network Exploration](https://arxiv.org/pdf/2109.09547)）。

### 方案：时光带 + 联动人物卡 + 关系链

人物 tab 分为 **时光 · 关系 · 名录**。

1. **时光**（默认）。顶部是一张横向的“时光带”卡片：保留 PC 版的横向生命线，但压成约 170px 高的细带，只当作可拖的时间刻度，不承担阅读名字的任务。中央固定一根渐变读数针，拖动时读出年份、所在时期和在世人数。下方是**那一年在世的人**的横滑肖像卡（显示“此时 29 岁”、生命进度、相关的人头像）。两者联动：拖时光带 → 卡片集合更新；左右滑卡片 → 时光带上这个人的生命线变成渐变色，其关系人变为金色；点时光带上的线 → 时光带滑到这个人中年，卡片也滑到这个人。附近 ±8 年内有“相遇”时，出现一张相遇卡片。
2. **关系**（关系链）。一次只看一个人：中心是大头像，周围最多 8 位直接关系的人，连线颜色区分师承、影响、对手、赞助、相遇。点周围的人，这个人从原位置飞到中心，新的关系人从中心弹出、连线依次描出；上方“足迹”记录走过的路径，可原路返回。下方按关系类型分组列出全部关系（含相遇事件标题），也是读屏可用的文字版本。
3. **名录**。二十次相遇的横滑卡片，以及按大时代分组的三列人物卡。

第五轮更新：时光带上的生命线改为带头像和名字的细胶囊（每行 21px）。名字贴在可视区左侧，长寿的人拖动时名字一直可见；古代或短命的人名字会伸出生命线，排行时按“头像 + 名字”的宽度占位。最多同时在世 17 人，所以仍是 17 行，时光带比原来高约 170px，下方肖像卡相应缩矮。相遇的菱形移到时光带底部单独一行，可直接点开，不再压在名字上。

人物页提供“在时光里看”（跳到这个人中年那一年并选中）和“关系链”（以这个人为中心）。

### 年表：时光带 + “此刻”面板（第五轮）

年表的价值在于“对齐”：欧洲分期、中国朝代、教会历史、历史大事、代表作品、艺术时期共用一条时间轴，一眼看到同一时刻各处发生了什么。原来的竖向列表按时期分卡片，每张卡片只能对照一行历史，失去了这种对齐。年表只有 6 行，横向放正好能读出名字，于是改为与人物·时光相同的操作方式：

- 顶部时光带：6 行（欧洲 / 中国 / 教会色块，大事圆点，作品缩略图，时期色条），左侧固定行名；长条目的名字贴在可视区左侧，拖动时始终可读。刻度沿用 PC 版的展开比例，可切到真实比例（按真实比例史前约占整条线的 84%）。
- 下方“此刻”面板：当前年份所在的艺术时期（可进展厅）、欧洲 / 中国 / 教会条目（点开看说明）、最近的一件历史大事（上一件 / 下一件可让读数针跳过去）、那些年的作品。文字都在这里读，不需要点中时光带上的小圆点。
- 点时光带上的任何一项，读数针先滑过去；大事和时期滑到后再打开详情，作品打开作品页。
- 年表和人物·时光共用年份，切换 tab 时互相跟随（人物时光只覆盖前 500 年以后）。
- 原来的按时期列表保留为“按时期列表浏览”。

## 4. 审查记录

逐页截图检查浅色、深色后修正的问题：

- 画海浅色下“画间”标题压在画作上 → 顶部和底部加与背景同色的渐隐遮罩。
- 时光带生命线用分组原色太重 → 改为 16%（不在世）/ 58%（在世）的淡色，焦点用渐变色，关系人用金色。
- 读数针与年份、提示文字重叠 → 调整针的上下端。
- 年份所在时期取错（1482 显示“哥特”）→ 取开始得最晚的那个时期。
- 关系链 10 个节点时上下被裁切、名字换行重叠 → 最多 8 个、头像以中心定位、长名只取最后一段。
- 展厅卡片编号被叠放的缩略图遮住 → 编号提到最上层、缩略图缩小。
- 取色光晕位置偏出屏幕 → 移到主图后方。

第五轮：

- 阅读页竖幅作品的 `.figs.stack` 与页面栈的 `.stack`（绝对定位铺满）重名，图片盖住了题目和选项 → 改名为 `.figs.vert`。这是第三轮遗留的问题。
- 画海标题背后仍能看到作品 → 顶部遮罩改为实色过渡。
- 时光带选中的人用深色太重 → 改用强调色、7px 高。
- 相遇卡片说明折行只剩一个字 → 单行省略。
- 深色模式下分段控件的选中块几乎看不出 → 单独的 `--seg-on` 颜色。
- 时光带内层用 padding 撑出的滚动范围不够，最右端（人物 1990、年表 1970）拖不到 → 内层宽度改为 `calc(带宽 + 100%)`。人物时光也有这个问题。
- 人物时光在没有人在世的年份（例如从年表带来的 644 年）会报错 → 没有焦点人物时不再查关系。
- 跳到某件大事时年份按像素换算会差几年（前 3100 显示成前 3092）→ 跳转时直接用这件事的年份。

## 5. 覆盖范围与未验证项

已实现：上述全部页面与手势，数据来自 `content/` 真实内容，收藏与阅读进度存本机，浅深色切换，减少动态效果时关闭动画。

未实现或仅示意：分享（只给提示）、原图加载在打包版中不可用、收藏多选编辑、横屏布局、读屏焦点管理；第二轮“脉络”中的艺术中心地图、派系与关系、理性与激情、并置看画、画有多大尚未放进原型。画海是简化的螺旋布局，不是正式版的三维镜头。

浏览器 375×812 模拟中检查过静态布局（`?still`）与主要交互逻辑：时光带拖动后的年份、时期、在世人数与卡片更新，点生命线跳转，人物页“在时光里看”，关系链换中心与足迹，名录，作品页取色，展厅、搜索、收藏、阅读页，深色模式。动效（入场浮起、缩放转场、关系链形变）在后台预览中无法逐帧观察，**未在 iPhone 真机上测试**，手感、玻璃模糊性能和 Safari 边缘返回冲突需真机确认。

## 6. 落地建议

正式做 iOS App 时按 [选型调研](ios-ui-options.md) 的推荐路线：SwiftUI 实现 tab、导航栈、sheet、搜索、上下文菜单和缩放转场；时光带可用 SwiftUI `ScrollView` + `scrollPosition` 读出偏移，关系链用 `matchedGeometryEffect` 做中心节点的形变；作品页顶部的淡取色可以直接用 `LinearGradient` 叠在 `systemGroupedBackground` 上。画海先用 WKWebView 承载现有实现。

如果先改现有网页手机端，可以直接沿用原型的 token、组件和交互规格替换 `src/mobile/`，并保留现有深链、历史记录和图片渐进加载。
