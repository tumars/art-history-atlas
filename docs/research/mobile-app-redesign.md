# 从长卷到随身美术馆：移动端第二轮设计

2026-11-06 · 调研、原型与正式手机入口实现；正式手机入口已替换；发布流程见 [部署文档](../deployment.md)。

## 1. 这次要改变什么

上一轮解决了窄屏溢出、看画顺序与基本返回，但主要模型仍是“同一篇网页，滚到另一节”。用户这次明确反馈操作不够原生，允许移动端整体重构。因此撤销上一轮“继续保留手机单页长卷、不做独立 tab 页面”的设计约束。**保留画海优先，改用独立页面、稳定的底部入口和可预期的返回层级。**

这里的“原生”指操作模型，不预设必须上架 iOS / Android App。先设计在 Safari / Chrome 内也自然的移动产品；主屏幕安装可以增强沉浸感，但不能成为正确返回、快速看画的前提。

本轮交付：公开资料与口碑调研、信息架构、关键页面、手势规则、技术边界和可操作原型。未经实测，不把竞品的具体手势或性能当作事实；也不把原型当成完整重构已经完成。

## 2. 调研方法与样本

选择有较大评价基数、与看画 / 理解艺术直接相关的四个产品，排除绘画创作工具、艺术品交易平台及名字相同的电视遥控器 Smartify。数据来自本轮读取的**美国 App Store** 页面，2026-11-06 记录；评分四舍五入、页面可能有缓存，不跨国家比较，不等于独立质量排名。

| 产品 | 页面显示的口碑信号 | 可核实的产品重点 | 对本项目的取舍 |
|---|---|---|---|
| [DailyArt](https://apps.apple.com/us/app/dailyart/id547982045) | 4.8 / 5，约 38K 评分；Editors’ Choice | 一件作品配短故事、作品与艺术家资料、检索与收藏 | 学它把一次观看做小、做完整；不把画海替换成每日单图，也不复制订阅、通知或打卡 |
| [Smartify: Arts and Culture](https://apps.apple.com/us/app/smartify-arts-and-culture/id1102736524) | 4.5 / 5，约 9.5K 评分 | 文化场馆、作品识别、导览、个人收藏 | 借鉴作品与导览衔接；本项目没有实体馆场景，不做扫码、购票或附近场馆 |
| [Connects: Arts+Culture / Bloomberg Connects](https://apps.apple.com/us/app/connects-arts-culture/id1476456847) | 4.8 / 5，约 7.6K 评分 | 场馆提供的专题与多媒体导览，可现场或远程使用 | 借鉴有明确主题、范围与下一站的导览；不承诺没有内容支持的语音讲解 |
| [Google Arts & Culture](https://apps.apple.com/us/app/google-arts-culture/id1050970557) | 4.7 / 5，约 133K 评分 | 高清作品、时间 / 色彩探索、专家策展与收藏 | 借鉴图像优先与多条探索路径；不搬入自拍匹配、AR 和其他偏离本项目主线的实验功能 |

公开口碑说明这些产品值得研究，不能证明所有交互都好。此次未安装并逐项操作四个 App；以下区分产品资料、用户评论与自己的设计推导。商店推广图也不能证明真实滚动、返回和动画行为。

### 评论带来的具体约束

- DailyArt 商店展示的 2023-07-24 评论肯定少量文字配作品、可以放大看细节；创始人 2023 年的[产品回顾](https://www.dailyartmagazine.com/story-dailyart-mobile-app/)也明确强调小份量内容。这支持“看一件”的任务设计，不证明当前版本所有界面细节。
- Smartify 展示的 2024-03-02 评论在肯定作品信息与收藏的同时，提到换搜索词时仍被先前范围限制。本项目全局搜索默认全部；局部筛选必须可见，不能把展厅范围静默带入全局搜索。
- [Connects 评论页](https://apps.apple.com/us/app/connects-arts-culture/id1476456847?platform=iphone&see-all=reviews)的 2024-02-09 评论提到返回不稳定、看相邻作品仍需退出重新输入。本项目必须在当前作品集合里直接切换，返回恢复原条目与位置。
- [Google Arts & Culture 评论页](https://apps.apple.com/us/app/google-arts-culture/id1050970557?platform=iphone&see-all=reviews)的 2024-06-09 评论提到收藏难找和横竖屏观看不便。收藏要直接可见，全屏看画随方向调整，不能让横屏把手机产品突然切回桌面长卷。

这些是可见评论中的问题线索，非系统抽样，不据此认定当前版本仍有相同缺陷或问题普遍发生。没有引用未经验证的刷评指控。

### 平台规则核对

Apple [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)建议用底部栏表达主要区域、保留各区域的导航状态，带清楚文字，避免把动作塞进 tab；[Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets)把 sheet 定义为与当前上下文相关的小任务，并提醒不要连续叠加多个 sheet。下述结构是本项目据此作出的设计决定，不是声称四个竞品采用完全相同的导航。

## 3. 当前体验为什么仍像网页

检查依据：`src/sections/mobile.ts`、`src/lib/navigation.ts`、`src/sections/lightbox.ts` 与现行设计文档。

| 当前模型 | 手机上的结果 | 第二轮决定 |
|---|---|---|
| 移动各分区 DOM，仍都处于同一个长页面 | 跳转后缺乏明确“进入一个页面”的感觉，位置依赖滚动 | 手机用独立页面容器；桌面保留长卷 |
| 目录承担主要目的地切换 | 常用入口藏在顶部弹窗，来回寻找 | 四个底部根入口始终可达 |
| 作品主要是从正文打开大图弹层 | “看作品资料”和“沉浸看图”混在一起 | 作品是普通详情页；全图才是临时全屏层 |
| 搜索 dialog 留在作品 dialog 下层 | 多层关闭与背景滚动锁增加心智负担 | 搜索是普通页面；筛选才使用单层 sheet |
| 返回依靠捕获多模块 DOM / 回调状态 | 页面、弹层、滚动与焦点交织，刷新不能还原临时栈 | 用可序列化路由状态表示内容与来源，局部状态归页面 |
| 年表、图谱直接搬进另一个大框 | 图表本身依然是桌面任务 | 先给手机列表 / 关系摘要，再提供专用画布页 |
| 横屏越过 700px 就恢复桌面组织 | 同一台手机旋转会改变产品结构 | 输入方式与可用空间共同决定布局，旋转只改排版 |

## 4. 信息架构

四个 tab：**画海 / 导览 / 探索 / 收藏**。这些是持久目的地，不是“返回”“放大”一类动作。顶部的“搜索”进入搜索页；设置集中在根页的更多入口，不承担主导航。

| 根入口 | 用户想做什么 | 页面内容 |
|---|---|---|
| 画海（默认） | 随便逛，遇见一件作品 | 全屏画海、非模态短展签、时期筛选、暂停 |
| 导览 | 有人带着看，形成理解 | 三分钟故事、十八间展厅、继续上次阅读；均来自现有内容 |
| 探索 | 找特定作品 / 人物，理解脉络 | 作品网格、人物列表、脉络入口；全局搜索与可见时期筛选 |
| 收藏 | 回到想再看的作品 | 本机收藏，空状态直接引导去看画；无需账户 |

收藏是这轮唯一新增的主要产品能力。它让自由探索有可回访的结果；首版仅收藏作品，使用本机存储，不增加登录、云同步、笔记、分组或社交。不能把原“藏品”与“收藏”混称：原藏品全量浏览归入探索，收藏只显示用户标记的作品。若本机存储不可用，应告知本次会话可用而非伪装保存成功。

普通子页面保留底部栏；全图查看器与专注故事阅读可暂时覆盖底部栏，使用明确“完成 / 退出阅读”。切换 tab 恢复该 tab 最近页面与滚动，重复点当前 tab 返回该 tab 根页。浏览器返回遵循实际访问顺序，页面左上返回只退当前层。首个深链接没有来源时回其所属根页，不强制退出网站。

## 5. 关键页面

### 5.1 画海：真正的首页空间

打开即见原有浮空画海，不放欢迎页、引导遮罩或每日单图。顶部保留小站名、搜索、时期筛选；底部栏上方是紧凑展签。原来的“大按钮进入十八间展厅”移除，导览成为稳定 tab。

- 画海独占主视口，不在它下面继续接正文。这样拖动只负责探索，不再同时承担翻网页的任务。
- 选中一件作品时突出该件，底部短展签更新标题、作者、年代，提供“看作品”和收藏。直接点同一件或“看作品”进入作品页；第一次点不立刻打断探索。
- 屏幕内部单指可二维拖动，保留分层位移与惯性；左右边缘约 24px 不启动自定义拖动，留给系统导航。双指交给浏览器缩放，不以 `touch-action:none` 全局禁用。
- 保留前后切件的按钮替代拖动，减少动态时关闭惯性与漂浮；暂停始终可达。时期筛选是小范围 sheet，选择即生效并关闭。
- 从作品页返回，恢复选中的作品、镜头位置与远近；切到其他 tab 暂停离屏动画，回来不重新飞到初始位置。

这是第二轮与上一轮“横拖画海、纵滑进入正文”的明确差异：没有正文长卷后，画海可以拥有完整二维空间。正式落地前必须真机验证与系统边缘手势、双指缩放的冲突。

### 5.2 作品页与全图：分清阅读和观看

作品页：返回 → 完整比例作品 → 标题 / 作者 / 年代 → 一段看点 → 相关故事 / 人物 / 时期 → 来源。常用动作只有放大与收藏；来源以清楚入口展开，不让一串署名压住第一屏。

在当前集合中切下一件：保留来源标签，例如“盛期文艺复兴 · 3 / 35”“搜索结果 · 2 / 8”；不能无提示跳入全站 423 件。首末不循环，末尾给“返回列表”。切件替换当前作品路由，避免返回要退出几十件作品。

全图查看器：暗场、完整比例、完成按钮；点击可收起工具栏，双击放大 / 复位，支持按钮替代。适应模式中左右轻扫可切件；放大后拖动只平移图片，不能切件；捏合中不触发换图。首次打开显示展示图，原图按需解码，失败保留可用预览。旋转保持作品与查看状态。

网页首版优先使用浏览器缩放与明确按钮，待专用缩放实现经过真机验证后再开启自定义双击 / 捏合。原型只演示放大按钮，不能据它宣称手势已经实现。

### 5.3 导览：入口先讲清楚要看什么

导览首页使用大作品图和具体问题，如“同样躺着，她为什么引起争议？”。每个入口带实际时长与步数；没有读过时不显示虚假的“继续”。三分钟故事与十八间展厅分区明确，不把所有介绍展开成列表长文。

展厅独立页：标题 / 年代 / 一个问题，代表作列表与“从第一件看”入口。时代背景单独阅读；图解从具体作品的问题进入。不在每件作品下面重复整厅背景。

故事阅读一次一小步，页面顶部显示当前问题与 `1 / 3`，中间作品，下方观察任务与可展开解释，底部一个“下一步”。允许回看与退出；完成显示“去看相关作品 / 回到导览”，不用考试、积分、连续打卡或不存在的语音按钮。

### 5.4 探索：搜索、索引、脉络分工

根页分段“作品 / 人物 / 脉络”；搜索框默认全局，进入搜索页明确显示“全部 / 作品 / 人物”。筛选作为可见标签，可一键清除。搜到作品后返回，键盘不自动再弹出，原关键词与结果位置保留。

作品两列轻网格，缩略图完整显示，标题与作者可见；列表渐进渲染。人物用有头像的列表，资料页有作品、人生与关系分段。关系先以人物为中心列出直接关联，点名字进入另一个人物页，图谱不是默认必经入口。

“脉络”收纳年表、艺术中心地图、派系关系、理性与激情、并置、尺度。每项进入自己的页面。时间轴先按时期浏览，选择后才展开历史对照；地图先有城市与时代说明；并置保留两张图同屏和局部放大；尺度共用真实比例。完整画布独占可用区域，提供复位、选择器和文字等价入口，不再包进窄弹窗里横滚一张桌面图。

### 5.5 收藏：让回访有入口

在画海展签、作品页均能一按收藏，再按取消；按钮状态与短反馈同步。收藏 tab 即时更新，刷新后仍在。空状态解释“把想再看的作品留在这里”，提供去画海入口，不显示登录墙。清空使用确认，删除单件提供撤销；首版不做排序系统和收藏夹。

## 6. 页面与手势的统一规则

| 场景 | 规则 |
|---|---|
| 根 tab 切换 | 图标 + 中文；保留各 tab 的栈、筛选和滚动，不滚整页寻找锚点 |
| 作品、人物、展厅、搜索 | 普通页面向内进入；返回上一级。正文仅一个纵向滚动区 |
| 时期、排序、主题 | 单层 sheet，选择 / 完成 / 取消；不叠第二个 sheet |
| 全图、专注阅读 | 临时全屏，完成 / 退出回原内容，底部 tab 暂时被覆盖 |
| 浏览器边缘返回 | 不自己实现全屏 swipe-back，不拦截系统边缘 |
| 横向手势 | 画海拖动、适应状态切图、局部缩略图；不绑定全屏 tab 左右切换 |
| 放大中 | 单指只平移；切图手势关闭；始终有复位按钮 |
| 键盘 / 辅助技术 | 与触摸有等价按钮，页面进入聚焦标题，返回聚焦原条目；隐藏页 inert |
| 反馈 | 按下立即反馈，普通过渡 180–240ms；不等待大图才允许返回；减少动态直接切换 |
| 软键盘 | 搜索结果适应 visualViewport；不把底部 tab 顶到键盘上；取消可达 |

纸色阅读背景、深蓝画海、暖金强调与艺术品本色保留。正文 16–17px，次级 13px，标题约 28–32px，触控热区至少 44px（Android 以 48dp 为参考）；图像与留白组织内容。拒绝给每段内容都套卡片，也不以模仿玻璃质感代替交互设计。

## 7. 内容迁移，不能因重构丢功能

| 现有内容 | 新位置 |
|---|---|
| 浮空画海及全部有图作品 | 画海根页，共用原有布局 / 投影能力 |
| 十八间展厅与 17 张图解 | 导览 → 展厅 → 作品 / 背景 / 图解 |
| 三分钟故事与现代艺术路线 | 导览；相关作品与人物页有入口 |
| 全量藏品与检索 | 探索 → 作品 / 搜索 |
| 人物、派系、生平与关系 | 探索 → 人物；脉络中的派系 / 关系画布 |
| 年表与艺术中心接力 | 探索 → 脉络 |
| 理性与激情、并置、尺度 | 探索 → 脉络，同时从相关作品可进入 |
| 来源、权利、推荐阅读、主题、源码 | 作品来源 / 关于与设置，保持可达 |

## 8. 实施设计：复用内容，替换手机页面组织

不要再向 `mobile.ts` 加分区搬运和弹层快照。建立独立的手机入口渲染层，共享 JSON、搜索、图片加载、画海数学模型和图解内容。保留桌面入口；同一内容模型，不维护第二份作品数据。

最小状态模型：`activeTab`、每个 tab 的 `Route[]`（类型、内容 ID、来源集合、局部筛选 / 步骤 / 滚动）、临时查看器、收藏 ID。记录 ID 与普通数据，不记录 DOM 节点、函数闭包或已销毁元素的引用。对应浏览器 history 保存可序列化条目；前进、后退、深链刷新都有明确恢复策略。

保留 `#p-*`、`#who-*`、`#story-*` 旧链接映射，新增作品可分享链接；非法 ID 给“未找到 / 回探索”，不留空屏。只挂载当前页面及必要的上一页缓存，离开销毁监听器、停止动画与请求；不为四个 tab 复制四份完整页面。

不预先决定 React / Vue 或重写所有代码。先用现有 TypeScript 实现一条完整纵向流程，验证页面栈和浏览器历史，再决定是否需要路由库。PWA manifest 可以后续添加；离线全站缓存、原生包装、推送、账户和服务端收藏均不在首版范围。

建议顺序：

1. 页面壳、四个根入口与路由返回；先完成“画海 → 作品 → 人物 → 返回画海”。
2. 专用作品页、全图查看器、全局搜索与本机收藏；验证从不同集合连续看画和返回。
3. 导览、展厅与三步阅读；迁移读过位置和局部选择。
4. 手机脉络页与图表入口；全内容可达、深链接与桌面回归后再替换正式手机入口。

不能先发布一个新的 tab 外壳，再把所有子页面接回旧长卷。上线门槛是主要任务链端到端完成。

## 9. 验收目标

这些是待实现时的验收条件，不是调研已经测得的改进指标。

- 首次打开直接是画海；四个主要目的地一次点击可达，普通详情仍能识别当前 tab。
- 画海拖动 → 看作品 → 作者 → 返回两次，回到同一个镜头与选中作品。
- 搜索 → 滚动结果 → 作品 → 下一件 → 返回，恢复原查询 / 筛选 / 列表位置；下一件范围不串。
- 收藏 / 取消 / 刷新 / 空状态可用；禁止伪造收藏数、阅读进度或“今日推荐”时效。
- 三步阅读退出再继续，不丢步骤与反馈；直接分享故事 / 人物 / 展厅链接正确落地。
- 每个常用任务没有三层 sheet，也不靠在不同 section 间来回滚动完成。
- iOS Safari 和 Android Chrome 真机测横竖屏、边缘返回、双指、软键盘、后台恢复、200% 文字与读屏；320–430px 无页面横溢出，横屏不变成桌面产品。
- 慢网可先看缩略图，返回不等待图片；首屏不创建全部高分辨率图片。记录真机交互延迟后才能谈性能改善。
