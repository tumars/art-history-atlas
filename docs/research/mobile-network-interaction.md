# 手机人物关系网络交互调研

2026-11-06。目标：保留 PC 版完整人物、关系与派系筛选，改善手机上的阅读和操作；本轮不发布。

## 现状与原因

上一版直接把 1000px 宽的图缩进手机正文。390px 设备上的总览缩放约为 0.35，30px 头像只有约 10px，名字难读、难点。页面上方的介绍、派系和图例占据首屏；点人物后，说明在画布下方，需要滚动才能看到。图内拖动与页面滚动交替，放大后也缺少直接定位手段。

## 参考与取舍

| 来源 | 实际参考内容 | 本次采用 |
| --- | --- | --- |
| [Apple HIG：Maps](https://developer.apple.com/design/human-interface-guidelines/maps) | 熟悉的平移缩放；帮助寻找位置；选中目标应明显区分；避免控件长期遮挡地图 | 画布作为主区域、提供人物定位、突出选中关系；筛选按需展开 |
| [yFiles：Touch Interaction](https://live.yworks.com/demos/input/touchcustomization/) | 单指平移、双指缩放、点选节点；编辑手势与导航需要区分 | 只提供浏览，不引入节点拖拽编辑或长按模式 |
| [Snyder 等：Interaction Techniques for Exploratory Data Visualization on Mobile Devices，EuroVis 2024](https://arxiv.org/abs/2404.11602) | 可发现性、就地探索、便于恢复；研究包含 12 人形成性试验，并非针对本站的验证 | 固定人物信息区、关联人物直接定位、显式缩放与总览按钮 |

以上是官方规范、公开示例和研究阅读，不是对艺术类 App 的口碑排名或真机对比试用。没有引入 yFiles：现有 SVG 已能呈现全部 67 位人物、96 条关系，问题主要在界面组织和镜头。

## 实施

- 人物列表进入关系网络后，占用导航栏与底部 tab 之间的完整页面；不再显示探索页的大标题和搜索介绍。
- 默认以达·芬奇为起点，按 1.6 倍显示约 48px 的头像，全部节点和连线仍在同一画布中；总览可随时查看全图。
- 顶部用原生人物选择器定位，五类关系开关和派系说明收进“筛选”；完成后回到画布。人物定位遵循当前派系范围。
- 点人物或下方关系卡片会将人物居中，下方固定显示人物摘要、生平入口和可横向浏览的关系卡片；不要求滚动整页寻找信息。
- 图内保留单指平移、双指缩放、键盘操作及显式缩放按钮；“定位”找回当前人物，“总览”取消突出并展示完整范围。
- 总览弱化名字，放大后呈现；选中时只显示相关人物姓名，其他人物头像仍保留，减少文字交叠。细描边不随缩放变粗。
- 限制镜头边界，避免将图拖到大片空白。保存派系、选中人物、镜头位置，返回和刷新后继续。
- 矮横屏使用左图右信息，避免底部卡片压缩画布；旋转后重新居中选中人物，保持探索对象可见。

## 验证边界

通过生产构建、Chrome 触控模拟、窄屏和深色截图、PC 关系图回归；浏览器脚本为 `scripts/mobile-network.e2e.mjs`。不将模拟测试视为 iOS / Android 真机或用户研究的结论。
