# 三万年长廊 · 设计文档

> 文档即代码：页面的功能、数据结构、交互规则以本文为准。改代码或内容结构时同步改这里，并在文末记一笔变更。

## 1. 定位

- **是什么**：一部可以动手玩的艺术史。先在“时间全景”里看艺术时期、历史大事、代表作品和几条背景历史如何对齐，再进入每个时期的“展厅”，用一张交互图解看懂这个时期最核心的一个概念。
- **原则**：能画出来的不用文字说；每个时期至少一张可以操作的图解；作品尽量配图，图片只用可授权的。
- **来源**：项目起于一份《大话西方艺术史》（意公子）的读书复盘页，开源时不再绑定这本书：文字内容按通行艺术史知识重写整理，这本书和《艺术的故事》一起列为推荐阅读。
- **通用性**：内容与代码分离。时期、作品、事件、背景历史都是 `content/` 下的 JSON，改数据就能增删内容；“体系”（tradition）是一级概念，目前只有西方艺术史，结构上可以加入中国艺术史等其他体系。

## 2. 页面结构（自上而下）

站名 **三万年长廊**（The Long Gallery）。口号：从拉斯科洞窟里的野牛，到纽约展厅里的小便池，沿着一条长廊走完西方艺术三万年。站名不写“西方”，是为日后加入其他体系留余地；具体体系名出现在副标题里。

0. **顶栏**（固定在顶部）：站名、分区索引（罗马数字 I–VI，滚动时高亮当前分区）、主题切换（跟随系统 / 浅色 / 深色）、GitHub 链接。顶栏下沿有一条细的阅读进度线。多于一个体系时出现体系切换。
1. **序厅 · 长廊**（three.js）：全宽的三维长廊。作品按年代顺序挂在两侧墙上，画框下有铜牌（作品名、年份）；每个时期的第一件作品前，地面上刻着时期名和起始年份。
   - 镜头默认缓慢前行（可暂停）；拖动画面、左右方向按钮或键盘 ←/→ 前后行走；页面滚轮不被劫持。
   - 左上叠加站名、口号和一行说明；右上是当前所在年份（大号数字）和时期名。
   - 底部是全长的刻度条：18 个时期按长廊位置排开，时期名上下两行交错以免重叠；当前位置有游标，点击刻度飞到该时期。
   - 画框光晕取所属大阶段的颜色；切换主题时长廊重建，颜色随之更新。
   - 点画框打开大图，列表为长廊顺序。
   - 不支持 WebGL 或用户开启“减少动态效果”时，退化为一条可横向滚动的作品带，信息不丢。
   - three.js 按需加载，不阻塞首屏文字。
2. **I · 年表**（原时间全景）：内容与交互不变（背景行、历史大事、代表作品、艺术时期、艺术中心接力），视觉上统一到新的字体与配色。
3. **II · 展厅**：
   - 时期导航改为细长的“展厅索引”：编号、时期名、起始年，当前项下方金色细线；横向滚动只滚动索引本身。
   - 左栏：罗马式大号编号、中文时期名、西文名（斜体衬线）、年代、主线（引文样式）、关键词、要点、历史背景。
   - 右栏：作品挂在“墙面”上（浅色衬底、柔和投影），下方是博物馆说明牌样式的展签：作者、作品名、年代 · 材质 · 馆藏、看点、图片署名；再下方是本厅作品缩略图。
   - 切换展厅时内容淡入（减少动态效果时直接切换）。
   - 深链接：`#p-<时期id>` 直接打开某个展厅，切换展厅时同步更新地址。
4. **III · 理性与激情**（钟摆图，体系里的说明文字放在图下）、**IV · 并置**（原对照组）、**V · 尺度**（原画有多大）：内容不变，视觉统一。
5. **VI · 藏品**（看片台）：只占约一屏，一次细看一件。
   - 上方：左边是作品大图（墙面色衬底，按原始比例完整显示，点图打开大图），右边是说明牌：所属时期（阶段色短线，点了跳到该展厅）、作者、作品名、年代 · 材质 · 馆藏、看点、图片署名，再下面是 ← n / N → 和“去××展厅”。
   - 中间：时期概览条，每个时期一段，宽度按作品数；当前时期加粗并显示阶段色，点某段跳到该时期第一件。
   - 下方：缩略图带，全部作品按时期、年份排成一条可横向滚动的胶片，按时期分组，组名吸附在左侧；当前作品上浮并加阶段色描边，切换时只滚动胶片本身，不带动页面。
   - 区域在视口中部时，键盘 ←/→ 换一件；手机上在大图上左右滑动换一件。切换时内容轻微淡入，减少动态效果时直接切换。
   - 大图列表为全部作品（与看片台顺序一致）。
   - 为什么不用瀑布流：68 件作品平铺要滚好几屏，看不出作品与时代的对应关系；看片台把“时代位置”（概览条 + 胶片分组）和“细看一件”放在同一屏里。
6. **大图**：桌面端左图右文，手机上下排列。←/→ 或按钮在当前列表里前后切换，显示“第 n / N 件”；点图片在“适应屏幕 / 原始大小”之间切换；Esc 关闭；展签含署名，可跳到所在展厅。
7. **页脚**：内容说明、图片来源与授权、推荐阅读、许可证与源码链接。

各分区的标题与导语：

| 分区 | 标题 | 导语 |
|---|---|---|
| I | 年表 | 把艺术放回历史里。欧洲、中国与教会的时间并排展开；选一件大事，看它在哪些时期留下了痕迹。 |
| II | 十八间展厅 | 每间展厅一个核心问题，配一张可以动手的图。 |
| III | 理性与激情 | 新风格常常是对上一代的反叛，钟摆就这样来回摆了几百年。 |
| IV | 并置 | 两件作品放在一起，差别自己会说话。 |
| V | 尺度 | 画册里一样大的画，挂到墙上可能差出几十倍。 |
| VI | 藏品 | 全部作品按年代排成一条胶片，一件一件翻看。 |

## 3. 内容数据（`content/`）

```
content/
├── site.json                       站点信息、时间轴分段、体系列表、推荐阅读
├── context/                        背景行，可被任意体系引用
│   ├── europe-periods.json
│   ├── china-dynasties.json
│   └── church-history.json
└── traditions/
    └── western/                    一个体系一个目录
        ├── tradition.json          名称、大阶段配色、艺术中心接力、背景行、钟摆配置
        ├── periods.json            时期（含图解标题与说明）
        ├── works.json              作品
        ├── events.json             历史大事（按年份排序）
        ├── comparisons.json        对照组（可选）
        ├── sizes.json              画有多大（可选）
        └── movements.json          20 世纪流派表，供“现代艺术”图解使用（可选）
```

类型定义见 `src/types.ts`，`scripts/validate-content.mjs` 检查必填字段、id 唯一和引用关系（构建和 CI 都会运行）。要点：

- **年份**：数字，负数为公元前。`yearText` 是给人看的写法（如“约前 450”）。
- **时期** `Period`：`id, name, short, en, span, start, end, group, mood(-2…2), thesis, keywords, points, bridge, diagram{id,title,caption}`。
- **作品** `Work`：`id`（小写字母、数字、连字符）、`title, artist, yearText, year, medium, location, summary, period`；`image.commons` 为维基共享资源文件名；仍在版权期的写 `copyright`（原因），不写 `image`；`timeline: true` 出现在时间全景。
- **历史大事** `HistoryEvent`：`year, yearText, name, what, art, periods[]`。
- **背景行** `ContextBand`：`id, label, theme(neutral|cinnabar|violet), fields[], items[{start,end,name,short,values[]}]`，可选 `intro`（导读卡）和 `emptyBefore`（某年之前留白并标注）。条目不能重叠，重叠的朝代按统一年份切开（如隋 581、元 1279）。
- **大阶段** `Group`：`id, name, light, dark`，运行时写成 CSS 变量 `--g1…--gN`，浅色、深色主题各一套。
- **时间轴分段** `site.axis.segments`：`[起年, 止年, 起点位置, 止点位置]`。目前前 30000–前 3000 占 13%，前 3000–500 占 23%，500–1400 占 14%，1400–1970 占 50%。

## 4. 交互图解（`src/diagrams/`）

- 接口：`Diagram { html(ctx): string; init(root, ctx): void }`，`ctx` 提供当前体系数据和 `groupVar()`。标题和说明写在 `periods.json` 的 `diagram` 里，代码只管画和交互。
- 注册：`src/diagrams/index.ts` 里 `体系 id → 图解 id → 实现`。时期的 `diagram.id` 找不到实现时，展厅不显示图解区。
- 西方体系 18 张图解（`src/diagrams/western/`）：

| 时期 | 图解 | 交互 |
|---|---|---|
| 史前 | 洞窟剖面：日光与火光 | 拖动火把往深处走，壁画动物逐个显现 |
| 古埃及 | 正面律人像拆解 + 等级比例 | 切换“心里知道的 / 眼睛看到的” |
| 古希腊 | 雕像姿态演变，肩线与胯线 | 滑块按年代变形 |
| 古罗马 | 梁柱 vs 拱券 | 加大跨度，石梁断裂而拱券稳住 |
| 拜占庭 | 金色马赛克 | 移动烛光，镶片闪烁 |
| 罗马式与哥特式 | 教堂横剖面对比 | 显示推力走向 |
| 文艺复兴早期 | 线性透视 | 拖动消失点，地砖和方块实时重算 |
| 盛期三杰 | 晕涂法 | 滑块让轮廓逐渐化开 |
| 威尼斯画派 | 素描 vs 色彩 + 两派传承线 | 滑块在两种画法之间过渡 |
| 北方文艺复兴 | 油画罩染层 | 增加层数，看颜色变深、光穿透反射 |
| 巴洛克 | 明暗对比 + 三角形 vs 对角线构图 | 拖动光源 |
| 洛可可 | 巴洛克 vs 洛可可风格指纹 | 静态对照 |
| 新古典主义 | 《荷拉斯兄弟之誓》构图骨架示意 | 显示直线 / 曲线骨架 |
| 浪漫主义 | 《梅杜萨之筏》双金字塔构图示意 | 显示构图线 |
| 现实主义 | 绘画题材等级金字塔 | 切换“库尔贝的挑战” |
| 印象派 | 一天中的干草堆 | 拖动时间；切换阴影画法 |
| 后印象派 | 四条出路流向图 + 点彩 | 悬停高亮；调点的大小看视觉混色 |
| 现代艺术 | 1890–1970 流派时间表 | 点击流派看说明（数据来自 `movements.json`） |

图解都是示意图，不复制原作画面。

## 5. 图片与授权

- **来源**：只用维基共享资源上公有领域、CC0、CC BY、CC BY-SA 授权的文件。仍在版权期的作品（毕加索、达利、沃霍尔）不放图，只给维基百科链接。
- **获取**：`scripts/fetch-images.mjs` 读取各作品的 `image.commons`，经 Commons API 取 1280px 大图和 320px 缩略图，检查授权，写入 `public/images/works/<id>.<ext>`、`<id>.thumb.<ext>`，并生成 `public/images/credits.json`（页面读取）与 `CREDITS.md`（人读）。不符合授权或找不到的文件会被跳过并列出。
- **运行方式**：GitHub Actions 的“从维基共享资源取图”工作流（手动触发，可选全部重下或只处理指定作品），完成后自动提交并触发一次部署。本地有网络时也可以 `npm run fetch-images`。
- **页面行为**：图片是否显示由 `credits.json` 决定，没有记录的作品显示首字占位，不会出现破图。大图下方显示作者、协议和来源链接。
- 部分 Commons 文件名来自早期整理，可能已改名或被替换；以取图工作流的报告为准，在 `works.json` 里换文件名后重跑。

## 6. 视觉与动效

- **配色**：主色取自艺术史上最贵的颜料**群青**（青金石），点缀色取**金箔**。浅色主题是“白天的展厅”：冷灰白墙面、墨色文字、群青强调；深色主题是“夜间的展厅”：蓝黑墙面、骨白文字、金箔强调。七个大阶段的颜色只用于数据编码（色条、边框、圆点），不用作装饰。
- **字体**：中文标题 Noto Serif SC（900 / 600）；西文标题、年份和罗马数字 Cormorant Garamond（含斜体）；正文 Noto Sans SC；数据小字 IBM Plex Mono。加载不到时回退系统字体。
- **版式**：内容最大宽 1200px，正文约 65 字一行；分区标题左侧是金色罗马数字，右侧标题与导语；卡片只用在需要“成为一个物件”的地方（展签、说明卡、图解面板），其余靠留白和细线分隔。
- **长廊场景**：深蓝黑空间、指数雾；地面是带微弱反光的深色石材；墙面暗灰，每幅画上方有一束暖色射灯光斑；画作贴图用缩略图，靠近时换高清图；时期名刻在地面。浅色主题下长廊同样保持夜间展厅的暗色，作为全站唯一的“暗场”。
- **动效**：只在三处使用：长廊的镜头移动、展厅切换的淡入、大图切换。全部遵守 `prefers-reduced-motion`。

## 7. 技术结构

```
src/
├── main.ts              启动：加载体系、写入配色、渲染页头页脚、初始化各分区；署名清单异步到达后重绘
├── content.ts           用 import.meta.glob 打包 content/ 下的 JSON；运行时读取 credits.json
├── state.ts             全局状态（当前体系、展厅、署名）与跨模块动作（goPeriod、openWork…）
├── types.ts             内容数据类型
├── lib/dom.ts, color.ts 小工具：转义、存储、拖动、分段按钮、颜色插值
├── sections/            hero（长廊入口）、timeline、hall、pendulum、comparisons、sizes、wall、lightbox
├── gallery3d/           three.js 长廊场景（按需加载）
├── diagrams/            图解接口、注册表、各体系实现
└── styles/main.css      样式（颜色全部走 CSS 变量，浅色 / 深色两套）
```

- **构建**：Vite + TypeScript（strict），`base: "./"`，产物可部署在任意子路径。`npm run build` 先跑类型检查和内容校验。
- **部署**：推到 `main` 后 GitHub Actions 构建并发布到 GitHub Pages。
- **记忆**：localStorage 记住上次的展厅和体系，读写失败不影响页面。
- **字体**：Noto Serif SC / Noto Sans SC / JetBrains Mono（Google Fonts），加载不到时回退系统字体。

## 8. 扩展到其他体系

1. 在 `content/traditions/<id>/` 建 `tradition.json`、`periods.json`、`works.json`（其余可选），在 `site.json` 的 `traditions` 里登记。
2. 背景行可复用 `content/context/` 下已有的，也可以新建（如“日本时代”）。
3. 需要图解时在 `src/diagrams/<id>/` 实现并在 `src/diagrams/index.ts` 注册；没有图解也能运行。
4. `npm run validate` 检查引用，`npm run fetch-images` 或取图工作流补图。

## 9. 已知简化

- 年代多为约数，作品取一个代表年份定位（如“约 1503–1519”取 1503）。
- “理性与激情”的 `mood` 是整理框架，不是学术定论。
- 背景行的分期是概括，用来对照，不是严格断代。
- 界面只有中文；类型和目录结构为日后加英文留了空间，但目前没有国际化层。
